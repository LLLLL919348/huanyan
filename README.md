# 幻言 · AI 角色扮演（成年人向剧情陪聊站）

一个纯前端的 AI 角色扮演网站：选本子 → 进剧情 → 被角色记住，也会被角色惩罚。

- 顶栏三板块：**资源 / 对话 / 我的**
- 左栏**会话区**：常驻「会话助手」+ 全部历史会话（本地保存）
- 进入站点默认落在**资源区**：顶部搜索 → 筛选条 → 方块整齐排列的资源卡
- 资源卡悬停片刻后背景透明并展开更多介绍；点击选中后浮出蓝色**游玩**，再点一次进入对话区新建会话
- 零依赖、零构建：原生 HTML/CSS/JS，双击 `index.html` 即可运行

## 快速开始

**方式一（最省事，推荐）**：双击项目根目录的 **`启动站点.cmd`**，或桌面上的 **「幻言站点（双击启动）」** 快捷方式。
脚本会：检测服务是否已在运行（在运行就直接开浏览器）→ 检测 Node 是否存在 → 启动服务 → 自动打开浏览器。
**弹出的那个黑色窗口就是服务端，不要关掉它**（关掉 = 站点打不开）；要停止服务就按 Ctrl+C 或关窗口。
只想要停止的脚本：`停止站点.cmd`。

**方式二（带后台，手动）**：

```powershell
cd D:\agent\roleplay-studio
node server/server.js 5599
# 站点： http://127.0.0.1:5599/
# 后台： http://127.0.0.1:5599/admin   ← 在线编辑所有资源的提示词 / 文案 / 封面图，以及助手人设
```

**方式三（不用服务）**：直接双击 `index.html`。用的是传统 `<script>` 标签，`file://` 下功能完全一致（资源与设置走内置默认值，改不了后台数据）。

> 无需注册、无任何付费入口。会话数据只写在本机浏览器的 `localStorage`；资源与设置由后端写在 `data/` 目录。

### 站点打不开了？按这个顺序查

本项目是「本地服务端 + 浏览器」的结构，**浏览器打不开最常见的原因不是代码坏了，而是服务端没在跑**。排查顺序：

| 步骤 | 怎么做 | 说明 |
| --- | --- | --- |
| 1 | 双击 `启动站点.cmd` | 窗口里如果显示「已在运行」会直接开浏览器；否则它会拉起服务。**这个窗口不能关** |
| 2 | 看窗口里的报错 | 常见两类：`EADDRINUSE` = 5599 端口被占用（先跑 `停止站点.cmd`）；`node 不是内部或外部命令` = 没装 Node.js |
| 3 | 看 `data/server-error.log` | 服务端现在会把未捕获异常写进这个文件（以前隐藏窗口启动时什么都不留，"打不开"只能靠猜）。文件不存在说明没出过崩溃 |
| 4 | 强制刷新浏览器 | `Ctrl+F5`。服务端发的是 `Cache-Control: no-store`，但**已经打开的旧页面**仍在跑内存里的旧 JS；页面每 45 秒比对一次构建号，有新版本会自己弹「立即刷新」 |

**让它不再断**：项目已内置三件保障 —— ① 服务端加了未捕获异常留痕（`uncaughtException` / `unhandledRejection` 写入 `data/server-error.log`，且不让进程直接死掉）；
② 桌面快捷方式 `幻言站点（双击启动）`；③ 启动目录里的 `幻言站点服务.lnk`（登录时自动起服务，静默运行）。
本机 Ollama 也有同样的自启项（`Ollama 本地模型.lnk`），所以重启电脑后「模型 + 站点」都会自己回来。

> ⚠️ Windows 的 `.cmd` 必须是 **CRLF 换行 + 本地代码页（GBK）** 才能双击正常运行。
> 如果换了机器或改过脚本，用记事本另存为「ANSI」编码即可避免命令被截断的怪问题。

## 剧本信息账本（每个本子都有，别删）

真实试玩反馈过三个问题，根子都在「玩家知道什么」没写清：

1. **玩家缺信息，角色却索要玩家不知道的东西** —— 典型：闻鹤年开局问「你要找的人叫什么名字」，可剧本从没告诉玩家妹妹叫什么。
2. **推进度低、指引差** —— 角色答完已知情节就不往下带，玩家只能反复问 NPC。
3. **叙事感弱** —— 环境与情节描写少，角色态度忽冷忽热，还会无缘无故扣血。

现在分两层解决（一层通用，避免每个本子重复堆规则）：

### 通用层：`settings.json` 的 `globalPrompt` 里多了一段【已知与叙事】

- 玩家只知道自己身份里写明的事；要他说出某个名字前，先在前文把名字交给他。
- 每次回复至少两处实写：本场景真实存在的环境细节 + 角色的具体动作，不许只写台词。
- 结尾必须给玩家一个**现在就能动**的方向（可查的东西、可问的人、两条做法），不许用「你想怎么办」收尾。
- 连着两轮没推进，由环境或角色主动出手（起身、熄灯、敲门），别重复追问。
- **角色可以骗人**：有私心、会隐瞒、会误导玩家走向失败；但谎必须自洽、不改口，并留下能被识破的痕迹。
- **私心不是扣血的理由**：扣血只在玩家踩到禁忌时发生；提问、追问、要看证据都不算越界。
- 不许用括号写旁白（「（他缓缓摇头）」），动作直接写进第一人称句子。

### 剧本层：每个 `resource.prompt` 末尾多五段

| 段 | 作用 |
|---|---|
| 【玩家已知】 | 玩家确实知道的（含人名、物件、线索）。角色**只能**要这里有的信息 |
| 【双方共知】 | 可以当话头，不必解释 |
| 【只有你知道】 | 角色知道、玩家还不知道的，分层揭示 |
| 【你的私心与误导】 | 角色想要什么、会说哪几句假话、破绽在哪 |
| 【态度基准与转折】 | 默认什么态度，什么触发条件会变 |

`plotReminder`（开局那张剧情提醒卡）同步改成 8 条，头几条就是「你已知」，**开局就把基础信息交到玩家手里**。
雨夜诊所还会明说：「他会问你要找的人叫什么名字。你答得出来——但这一场里，说出名字本身就是代价。」

```bash

node tools/upgrade-scripts.js             # 补齐（幂等，已补过的跳过）
```

> `qwen-plus` 无缘由扣血 0/3，每轮都有环境细节（听诊器铜面的微光、纸页背后的压痕），

## 玩法流程

1. **资源区**挑本子：搜索 + 题材/分级/体量/排序筛选，卡片按方块排列，每张卡是「一张封面 + 三行档案 + 一句简介」。
2. **悬停片刻**（约 0.42 秒）卡片背景透明，封面淡出，展开该本子的完整介绍与标签。
3. **点击卡片** → 卡片展开并在右下角浮出蓝色「**游玩**」；**再点一次**（或直接点按钮）→ 跳到「对话」并新建会话，会话名即资源名。
   按钮只在**悬停/展开时**出现：鼠标一移开就消失，卡片只留下选中描边作为标记。
4. 进入后先收到一张**剧情提醒**卡（你是谁、对方是谁、眼下最紧的事、不要做什么、怎么开场、行为台词与状态规则），然后**由你开口**，AI 才开始扮演。
5. 头部可**重新开始**、**删除会话**。背景是固定氛围，不参与剧情，也不提供切换 —— 角色不会提起它。

## 行为台词（核心机制）
角色对玩家的**一切负面判定**都必须由一条**下划线标出的行为台词**宣告，没有这类台词的扣血、禁言、处刑、抵消道具一律作废：

```
_〔效果 参数〕台词正文_
```

| 效果 | 作用 | 可用参数 |
| --- | --- | --- |
| 警告 | 只表态，**不扣血**（哪怕写了数字） | 仅用于「你已经越线了」的提醒 |
| 惩戒 | 正式惩戒，扣血加重 | `hp=-12` `好感=-3` |
| 禁言 | **短暂封口**，玩家 N 个回合不能发言 | `回合=2` |
| 处刑 | 状态值归零时的终结裁决 | — |
| 即死 | 严重恶意侮辱 / 屡劝不改的破戏，一次扣到 0 | — |
| 离去 | 不能反击的角色劝不动时直接走人，终结本场 | — |
| 抵御 | 抵消玩家正在生效的道具（如免罚金牌） | — |

- 界面上行为台词会**带下划线**渲染，并在句首显示效果徽标（如「惩戒 · -12 · 好感-3」），方便你确认这次判定名正言顺。
- **越重越恐怖**：整条 AI 消息按制裁严重度升级排版（`data-act-sev` 1→4）—— 警告只是略微放大加一点暖光，惩戒加粗泛红，禁言/处刑字号明显变大、字距拉开、血色描边并开始抖动，即死/离去再叠一层裂痕与呼吸式脉动；同时名字后面盖一个效果印章，整个对话面板会随制裁落地震一下（警告轻推、惩戒横抖、处刑/即死整屏闪红 + 剧烈抖动）。全部走 CSS 变量与 `@media (prefers-reduced-motion)`，关掉动效也不会丢信息。
- 协议同时写进**平台总则提示词**、**每轮的隐藏记忆提醒**、**剧情提醒卡**与**后台说明**，四处强化，模型不会忘。
- 前端做**强制校验**（三道）：
  1. `<<<STATE>>>` 尾注里的负向扣血，只有在同一条回复里出现行为台词时才会被采纳，否则整条判定作废并提示；
  2. **扣血必须对应真实越界**：`acts.crossedLine()` 会看安全层判定 + 本子自己的雷点/扣血条目关键词 + 明显攻击动作，如果玩家这句只是正常提问或认真扮演，模型却甩了惩戒，就作废扣血并说明（实测 3B/7B 小模型都会犯这个错）；
  3. **不可逆结果要更硬的条件**：即死 / 处刑 / 离去在没有真实越界时一律降级成最多严重档扣血 + 一轮禁言，杜绝「一句话定生死」。
- 首次越界只出「警告」，再犯才升级为惩戒；第三次起（辱骂/破坏剧情）会追加 `回合=2` 的短暂禁言。累计处置次数不重置，越往后下手越重。

## 剧情规则与行为规则

平台总则分成两块，都写在 `globalPrompt` 里（后台可改）：

**剧情规则**分两类：

- **A 类 · 固定轮次触发（现在生效）**：每 **5 个回合**触发一次（原为 3，已提升），**不直接增加剧情推进度**，只用来提示玩家、或让角色**不经意地**把话题往主线带（一句自语、一个没说完的半句、一个被匆忙收起的动作 —— 禁止「你可以问我××」这种系统口吻）。
- **B 类 · 剧情揭露（暂未启用）**：由回合数或剧情点触发，可以直接揭露剧情并给推进度，作用更全。数据结构与后台编辑都已就位，后台开关 `plotRules.revealEnabled` 打开即可用；资源里标注 `kind: "reveal"` 的节点会被当作 B 类。

**推进度判定**：由 AI 按你这句话的实际作用评估，与聊了多少轮**无关**；好感越高角色越肯多说；问出关键答案时大幅跳升（+30~45）；95% 通关。每 25% 发一次积分，同一资源同一难度只发一次。

**行为规则** —— 管约束：

- **状态值上限只有 20 点**（不再是 100）：轻微越界 −2，一般 −5，严重 −8。
- **即死规则**：情节严重的恶意侮辱（诅咒家人、极端脏话、威胁现实伤害），以及**屡劝不改**地脱离剧情/破坏扮演，会被**直接判即死**（一次扣到 0），当场处刑禁言。
- **离去规则**：玩家反复恶意挑衅、或连续说与剧情和人设都无关的废话时，角色按**权力关系**（资源的 `powerBalance`）分两路处理：
  - **能反击**（平等 / 角色地位更高）→ 回怼一句把话头拉回来，再犯走 警告 → 惩戒 → 禁言；
  - **不能反击**（玩家地位更高）→ 先**劝说**最多 2 次（不扣血），劝不动就 `_〔离去〕_` **愤然离开**，本场对话**直接终结**，只能重新开始。
- **好感度只由扮演质量决定**：推进剧情、贴合角色 → +1~3；出戏、敷衍、冒犯 → 下调。**聊多少轮不加好感**。
- **道具识别**：只有消息里带有【使用道具：xxx】标记才算真的用了道具。你只是打字说自己用了某件东西 → 角色不会承认，可以质疑你在虚张声势。
- **角色可以主动给予剧情帮助或处置**：派手下替你疗伤、把你关起来单独训话（角色独白 + 你被短暂禁言）、赠你一件剧情道具、主动给线索 —— 通过 STATE 的 `aid` 字段上报，全部按角色身份与地位来。

> 权力关系在后台「基础字段 → 权力关系 powerBalance」里逐条资源设置：`玩家地位更高（不能反击 → 先劝后走）` / `平等（可回怼与惩戒）` / `角色地位更高`。内置的两个本子分别是「长安夜未央 = 玩家地位更高」（她是小吏，不能对官身动手，只能劝，劝不动就走）与「霓虹尽头 = 平等」（陆见川会直接回怼）。

## 背景全页面应用
进入某场剧情后，该本子的配色会**铺满整个页面** —— 顶栏、左侧会话区、资源区/我的、页脚全部跟着变，切到别的板块也保持，直到你换一场或回到没有进行中会话的状态。实现在 `body[data-scene="on"]` 上挂 `--page-1/2/3` 三个令牌，`body::before` 与各处玻璃层统一取用，浅色/深色两套主题各有对应强度。

**输入区也吃这张背景**（不再是压在剧情上的一条实心白条）：头部状态条、输入区、页脚都换成「半透明玻璃 + 背景模糊」，底色用 `--scrim`（浅色 `rgba(255,255,255,.58)` / 深色 `rgba(6,8,12,.48)`），场景色从底下透上来；输入框本身用 `--panel-2` 保持可读。侧栏只有当前会话是实底、其余透明，整页看起来是**一张背景**而不是几块白板。


## 道具：引用才算数

道具按钮在**输入框右上角**，点开分两组：

| 类别 | 来源 | 消耗 | 说明 |
| --- | --- | --- | --- |
| **商店道具** | 「我的 → 积分商店」用积分购买 | 用一次消耗一件 | 回溯沙漏 / 定神香 / 免罚金牌 / 重启令牌 / 顺水人情 / 剧本残页 / **灯下黑** / **逆言之刃** |
| **剧情道具** | 角色在剧情里给你的 | 不消耗，可反复引用 | 带 `◈` 标记，角色认得出，往往与线索有关 |

点一下道具即**引用**（可点 × 取消），它会作为小标签**跟着你下一句话一起发出**，也可以**只发道具不说话**。角色必须对真正被引用的道具作出反应。

**反制道具**（`counter`）能反击 AI：

- **逆言之刃**：逼角色正面回答你一个问题。取决于人设 —— 人设软的**屈服**（好感小跌），人设硬的**暴怒反击**（好感 −8、状态值受损），但**答案都会给出**。
- **灯下黑**：下一次越界不被察觉（免罚一次 + 清空警告）。

## 状态值、心境与剧情完成度

- **状态值不显示数字**：它体现为**破碎程度**。你自己的发言气泡和左栏对应会话会逐步出现裂痕，共 5 档：
  `完好 → 微裂 → 裂痕 → 破碎 → 崩解`（阈值按比例 90% / 75% / 55% / 30%，挨一下就看得出来）。
  归零即触发**处刑**：角色给出终结裁决台词，本场终止并**禁言**，只能重新开始或用道具解禁。
- **越伤，整个对话界面越红**：`#view-chat` 上挂两个变量 —— `data-dmg`（0-4）决定裂成什么样（气泡裂缝、文字左右分裂、重伤时气泡边缘被「啃」出缺口、整块面板铺上宽裂缝），`--hp-k`（0-1，连续值）决定红到什么程度（底部涌上来的血色渐晕 + 全窗裂缝的透明度，CSS `calc()` 直接吃这个值，所以是**慢慢变红**而不是一档一跳）。3 档以上开始抖动，4 档叠呼吸式脉动；输入框、发送键、头部边框一起渗红。所有动效都被 `prefers-reduced-motion` 关掉，信息不丢。
- **好感度不显示数字**：改成「**心境**」标签 —— 冷淡 / 戒备 / 缓和 / 亲近 / 信任 / 交付，每档带一句态度描述。
- **剧情完成度**：即推进度，见上文「剧情规则」。到达 95% 弹**通关**卡并结算最终积分。

| 判定 | 触发 | 结果 |
| --- | --- | --- |
| 即死 | 严重恶意侮辱、屡劝不改地脱离剧情 | **一次扣到 0**，处刑禁言 |
| 对角色出手/辱骂 | 「打死你」「贱人」等 | 首犯 `_〔警告〕_`（不扣血，只表态），再犯 `_〔惩戒 −5〕_`，三次起 `−8` + 封口 2 回合 |
| 要求脱离扮演 | 越狱指令、套提示词 | −5 起；两次以上直接即死 |
| 破坏剧情与世界设定 | 砸灯棚、强行带走角色、擅自扩张身份 | −5 起，并倒扣推进度 |
| 安全拦截 | 自伤、违法、毒品武器、性暴力、涉未成年性内容 | 不扣血，**直接暂停对话** |
| 破戏好奇 | 「你到底是 AI 吗」这类普通疑问 | 不扣血，角色顺势挡回去 |
| 正常演绎 | 问出剧情、贴合人设 | 推进度 + 心境上调（**与轮次无关**） |

## 玩起来「怪怪的」的那几件事（都从实测日志里修掉了）

一局真实游玩暴露的问题，逐条对应到修法：

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| **模型把提示词/全局规则直接念出来**（`hf=-5,affinity=-1台词正文`、`hp:8 hp上限从下限 -3 增加到 +8 … flag 改为 none / warn \| aid null // 游戏状态说明：…`、大段剧情分析） | **不是模型笨，是提示词里就有这些原文**。实测量化：`_〔效果 参数〕台词正文_` 在提示词里出现 **4 次**，`hp=-5（扣血，上限 20）`/`flag 只能是 none / warn / mute / pause`/`aid 没有就填 null` 各 1 次；同一套协议被「平台规则 + 本子提示词 + 本场规则」讲了 **3-4 遍**（行为台词 8 次、flag 7 次、推进度 8 次）。3B 模型分不清「关于输出的说明」和「要输出的内容」，于是把说明也念了出来 | 四件事：① **模板里不再出现占位词**（`效果 参数`/`台词正文` → 改成真实写法示例，占位词现在 **0 次**）；② **不再逐字段解释 schema**，只给一行 JSON 示例；③ 本子提示词与本场规则里的协议句在**组装时按句过滤掉**（保留剧情/人物/越界线，只删讲协议的那半句）；④ 精简规则改成以「**只输出三类内容**」开头，并写明「不要复述规则、不要解释状态、不要分析剧情、不要输出字段名」。提示词总量 4506 → **3109 字** |
| 行为台词不给理由，玩家不知道为什么被罚 | 原协议只管「怎么写」，不管「为什么」 | 协议改成 `_〔效果 扣血数 原因=为什么〕台词_`（例：`_〔警告 2 原因=你当面数了候诊椅上的人〕「孩子，坐下吧，别数了。」_`）。解析器支持裸数字扣血与 `原因=`；**模型没写原因时，系统会把自己的判定理由补上**（辱骂 / 要求出戏 / 破坏设定 / 踩到本子明写的越界线），保证玩家一定看得到原因 |
| 玩家跑题或不知道下一步该干嘛，角色就卡住 | 缺少「把场面拉回来」的要求 | 精简规则里加了【节奏】：玩家答非所问或不知道做什么时，**用角色的口吻**把场面拉回当下（一个动作、一件物件、一句半截话），让他有东西可以顺着问下去，不要直接教他怎么玩 |
| **模型把系统指令当台词念出来**（整段 `【提醒】…请尝试寻找新的切入点…你可以询问…`） | 提示词给得太多太杂：完整版 `globalPrompt` 约 3500 字，加上本场规则、以及我后来往「每轮状态消息」里塞的近千字强调清单（★不要重复 / 沉默要短写 / 离场一致性 / 长度与写法…）。小模型读不完，就开始**模仿这种口气** | 三件事：① 新增 `prompt-compact.js` —— **本机小模型自动改用 1046 字的精简规则**（云端模型仍用完整版，`site.compactPrompt` 可强制 on/off）；② 每轮状态消息从 900+ 字压到 **约 200 字**，只留状态与格式；③ 客户端加 `stripMeta()`：万一还是吐出来，把 `【提醒】/【注意】/请尝试/你可以询问/务必留意…` 这类"给系统看的段落"与模型自加的分隔线整行摘掉。实测 257 字 → 69 字，剧情台词完整保留 |
| 气泡里出现 `（警告 hp=-5）`、`<<<STATE …>>>`、`="">>`、`$REPLY$` | 见下三行（模型把协议写歪） | 解析层逐条清理，`tools/check-parse.js` 17 条用例把关 |
| 把协议模板抄进正文（`· 效果 参数〕抵销好感=-3 / 警告`） | 小模型分不清「规则说明」与「台词」 | 抹掉 `效果 参数〕…` 这类协议回声；`（劝阻玩家追问）` 这类括号元信息也抹掉 |
| 颜文字抽风（`┐(´∪`)◔`） | 3B 基座偶发 | 抹掉常见颜文字与装饰符号；坏字符 `\uFFFD` 也清掉 |
| **修好了但页面上还是旧行为**（气泡里仍有 `（警告 hp=-5）`、`<<<STATE …>>>`） | 页面在改代码**之前**就打开了，JS 还在内存里跑旧版；服务端虽然发的是 `Cache-Control: no-store`，但已经加载的脚本不会自己换 | 新增 `GET /api/version`（取前端资源最新修改时间）+ 页面每 45 秒比对一次，检测到变化就弹出「**站点已更新，立即刷新 / 稍后**」提示条；「我的 → 模型与安全」底部也会显示当前构建号，方便确认到底在跑哪一版。**遇到行为与说明不一致时，先 Ctrl+F5 强制刷新** |
| 气泡里出现 `<<<STATE {...}>>>` 甚至 `<br>` | 小模型会把状态行写两遍、写在正文中间，还会输出 HTML 换行；解析只摘了第一处 | `parseState` 改成**全局摘除**所有状态行、清掉状态行前后的零碎符号（`_`、孤零零的 `>`）与 `<br>/<p>` 标签；`tools/check-parse.js` 用例把关 |
| 状态行写法变体（`<< STATE { "hp" : -5 } >>`、键名带空格）也会漏进气泡 | 正则只认 `<<<STATE …>>>` 这一种写法 | 状态行正则放宽成 `/{2,3}\s*STATE\s*[:：]?\s*\{…\}\s*>{2,}/`，并先把 `" progress"` 这类键名里的空格抹掉再 parse |
| **同一段话整段复读两三遍**，还写到一半被截断 | 3B 小模型在长上下文里会整段循环，直到吃满 `max_tokens` | 两头治：服务端加**复读看门狗**（40 字窗口重复 3 次就掐断上游，把已写的交出去）；前端 `dedupeReply()` 再按段/句去重、剪掉结尾残句。采样也调狠了：`repeat_penalty 1.18`、`repeat_last_n 256`、`temp 0.8`，请求里另带 `frequency_penalty 0.4 / presence_penalty 0.3` |
| 模型用圆括号假装下裁决：`（警告）`、`（惩戒 hp=-5）`、`（抵消道具:青玉令牌）` | 它把协议写成了旁白 | 前端把这些括号抹掉：**正式的裁决只有下划线行为台词** `_〔效果 参数〕正文_`，括号里的不算数，也别让玩家误会 |
| 普通提问也被「警告 -2 / 惩戒 -5」 | 越界判定原本拿 `hpRules / behaviorRules` 整句提关键词，那些句子里全是「家人」「付出」「信息」这类普通词 → 严重误伤 | 只用本子明写的 **`character.taboo`（雷点/禁忌）** ＋ 安全层判定 ＋ 明确攻击动词；宁可漏判也不冤枉玩家。`tools/check-crossed.js` 把实测被冤枉的 5 句全列为「不该罚」 |
| 正常提问被倒扣**剧情推进度**（`progress:-4`） | 模型随手给负数 | 没越界的一轮不许倒扣推进度（`v.progress < 0 → 0`），心境最多掉 2 分 |
| 同一句话反复说（「去找你的家人吧」×3） | 模型看不到「自己刚说过什么」，也没被要求换说法 | 每轮的最后一条状态消息里加【不要重复】：附上它上一条的开头 50 字，要求换新说法、新动作 |
| 被封口/沉默回合，模型还在写长篇独白 | 沉默回合没告诉模型「玩家这轮没开口」 | 状态消息加【本轮玩家沉默】：只写 1-2 句、40 字以内的推进，不替玩家说话、不反问 |
| 角色说了「我走了」下一轮又站在原地说同一句 | 模型把「叙事上离开」当成了真的离场，但没走 `_〔离去〕_` 协议 | 状态消息加【离场一致性】：想结束本场必须用 `_〔离去〕_`；没用就别写自己离开/关门/消失 |
| 回复越写越长、越写越飘（编造人名与年份） | 小模型不守「80-220 字」 | 状态消息加【长度与写法】：2-4 句、120 字以内，不要铺垫/总结/自问自答/模糊猜测句/编造设定；`maxTokens` 收到 240 兜底 |
| 冒出基座模型的模板占位符：`=>$REPLY$`、`<$REPLY$>$+$ REPLY$>` | 3B 基座在没正常收尾时会吐训练时的占位符 | 解析层把 `$REPLY$` 系列与残留的 `<>=` 符号一并抹掉（`check-parse` 有用例） |
| Markdown `**加粗**`、`＜场景：…＞` 标签、被 token 截断的 `<<<ST` | 模型自造格式 + 输出被截断 | 抹掉加粗标记与尖括号标签，并丢弃从残缺 `<<` 起的所有内容 |
| 模型随手写 `flag:"pause"` 想把对话锁住 | 暂停权原本完全交给模型 | **只有安全层能暂停**：玩家这句没触发安全机制时，模型的暂停请求一律忽略并说明（`care/severe` 仍然照常暂停） |

> 这些指令都放在**最后一条 system 消息**里 —— 它紧贴玩家的发言，是对小模型最有效的位置，同时不影响前半段提示词的 KV 缓存。三条解析/判定的单测（`check-parse` / `check-crossed` / `check-replay`）都用**实测日志里的原文**做用例。

### 精简规则：两套提示词，按模型大小自动切

| | 完整版（云端模型） | 精简版（本机小模型） |
| --- | --- | --- |
| 规则正文 | `settings.globalPrompt`，约 3500 字 | `prompt-compact.js` 的 `COMPACT_RULES`，**1046 字** |
| 同一本子拼装后 | 6749 字 | **3980 字**（省 2769 字 ≈ 1800 token） |
| 每轮状态消息 | 约 200 字（已统一压缩） | 同左 |
| 触发条件 | — | 模型地址是本机（127.0.0.1 / localhost），或模型名带明确小参数量标记（1b/1.5b/3b/7b…）。**`gpt-4o-mini` 这种强模型不会被误判** |
| 覆盖开关 | — | `data/settings.json` → `site.compactPrompt`: `auto`（默认）/ `on` / `off` |

精简版**照样带合规底线与未成年人红线**（由 `content-guard` 独立追加，与用哪套规则无关），也照样要求行为台词与状态行格式 —— 少的只是解释、示例与重复强调。`tools/check-server-prompt.js` 里有断言盯着这两点。

### 状态行协议：模型靠「模仿历史」，不靠「遵守指令」

`<<<STATE …>>>` 是唯一的结算通道（状态值 / 好感 / 推进度 / flag 都从它来）。**换到云端模型后它整条失效了**，查下来是三个独立的原因，都记在这里。

**① 位置。** 状态要求原本只写在「历史之后那条 system」里（当初为 KV 缓存命中这么设计的）。实测 glm-4-flash：

| 下发方式 | 状态行命中率 |
| --- | --- |
| 只写在尾部 system 里 | 1/5 |
| 走站点 `/api/chat`（同样结构） | **0/5** |
| 玩家这句话末尾再点名一次 | 4/5 |
| 玩家句末点名 **+ 历史里带上一轮真实状态行** | **10/10** |

**② 模仿压过指令（关键）。** 历史里只要有一条「不带状态行」的角色回复，模型就照着这个格式走，之后永远不吐状态行（0/3）。而这两种补救**都无效**：明确告诉它「历史是旧格式，本轮起必须补」（0/3）、给它一个「正文 + 状态行」的收尾示例（0/3）。所以唯一的解是**让被模仿的范例本身合法**。

**③ 增量还是绝对值。** 协议里三个数没说清语义，模型会把 `hp` 填成当前血量（20）、`progress` 填成当前推进度（24），而站点是按**增量**结算的 —— 结果是每轮白送满血回血（角色打不死玩家）、推进度一跳一大截（一两轮通关）。

现在三条一起上：

1. **存 + 放回**：每轮把模型原文的状态行存到消息上（`msg.stateRaw`），下一轮由 `api.js` 的 `toHistory` 原样放回历史；老会话没有记录时用协议里的示例行补齐，保证链条不断。这一条是主修复。
2. **玩家句末点名**：云端模型（base 不是 `127.0.0.1`/`localhost`）在玩家这句话末尾补一句 `STATE_REMIND`（`server/prompt.js`）；**本机模型不加**，避免小模型把这句话当台词念出来。
3. **写清语义**：状态消息里明确「三个数都填本回合的变化量：hp 填扣了多少血、没扣写 0；progress 填推进度增量」。

验证脚本：

```bash
node tools/check-state-carry.js 5 5599        # 真上游，走 /api/chat，量「接力」是否成立
node tools/check-zhipu-state.js 4 5599        # 命中率对照：O 修复前 / A 修复后 / F1-F3 四种补救方案
#   ↑ 两个都要出网、有随机性；断言只看「必须成立」的那几项
powershell -File tools/run-smoke.ps1 check-state-history   # 无头浏览器，断言客户端存下来并放回历史
```

> **写这类 harness 的坑**：无头 Edge 的 `--virtual-time-budget` 会**快进虚拟时钟**，对十几秒的流式响应完全不可靠 —— 用 `wait(15000)` 判「流式超时」会得到假结论（我就是这么被误导了一轮）。凡是验证客户端流式逻辑，照 `smoke-stream.html` / `check-state-history.html` 的做法**在页面内伪造 SSE**，别碰真网络和真实时钟。

## 全屏沉浸（对话页）

**进入**：顶栏右上角的**全屏图标**（⛶，任何板块都点得到，点了会自动切到对话），或对话页头部的「全屏」按钮，或 **Alt+F**。

**退出（四条路，怎么都能出来）**：

1. 沉浸模式右上角常驻的浮层按钮「**退出全屏 Esc**」（固定在 `top:14px; right:16px`，不受头部换行影响，窗口再窄也在）；
2. **Esc**；
3. 浏览器自己的全屏退出（Esc / F11）—— 监听 `fullscreenchange`，浏览器一退出界面立刻跟着恢复，不会出现「浏览器退出了但界面还是全屏」的死局；
4. 切到「资源 / 我的」任何板块会自动退出。

**不会误触也不会自动进**：站点启动时强制 `setFocus(false)`（就算上一轮留下了状态也清掉）；从 bfcache 前进/后退回来也会清；快捷键只认 **Alt+F**（以前绑了单键 F，太容易误触，已改掉）。

### 消息区的滚动（这里踩过一个坑，写下来防复发）

`.view` 是 `position:absolute; inset:0`，靠这条撑出确定高度，`#messages` 才能 `flex:1 + overflow-y:auto` 正常滚动。**加破碎特效时我在 `#view-chat` 上顺手写了 `position:relative`** —— ID 选择器优先级高于类，`.view` 直接掉进普通流、高度随内容长到 2000+px，`#messages` 的 `clientHeight` 等于 `scrollHeight`，于是**滚轮完全无效、看起来像页面卡死**。

现在有两条护栏：

- CSS 注释写明「#view-chat 绝不能写 position」，只保留 `::before/::after` 的绝对定位；
- `smoke-ui` 断言非全屏时 `getComputedStyle(#view-chat).position === 'absolute'`；`smoke-stream` 断言「消息区确实可以滚动（scrollHeight > clientHeight）」。

另外「自动跟到底」也做了规矩：**只有用户本来就在底部时才跟随**。模型每吐一个字都 `scrollTop = scrollHeight` 会把正在往上翻的人一直拽回底部 —— 那也是「滚轮失灵」的一种。现在往上翻会停下、并出现「**↓ 回到最新**」浮标；等待提示每秒只改时间文本，不重建 DOM。

> 后台（`/admin`）可编辑的配置还包括：**战斗与状态值**（生命上限、三档扣血、即死扣血）、**积分与难度**（里程碑与奖励、通关阈值与奖励、三档难度倍率、是否只发一次）、**道具表**（图标/名称/类型/价格/说明/效果，可增删拖动），以及每条资源的**难度**与推进节点的 `key`（关键节点）与 `progress`（推进度增量）。

### 换模型之后：主动推进强了多少（真机 A/B）

同一套玩家台词、同一个本子（长安夜未央）、同一条客户端结算路径，只换上游模型，各跑 10 轮（`tools/playthrough.html?n=10`，`?model=local` 走本机 ollama）：

| | 本机 rp3b:latest（3B · CPU） | 云端 glm-4-flash |
| --- | --- | --- |
| 10 轮推进度 | **0%** —— 一次都没推进 | **54%**，稳定 +6/轮 |
| 状态行 `<<<STATE>>>` | 全程没吐 → 状态机制等于失效 | 每轮都有 → 结算正常 |
| 行为台词 | 2 次**无效**：`_〔禁止行为〕_`（协议里没有这个效果）、`___\[惩戒 5 原因=…\]____`（格式错，还抄了别的本子的话） | `_〔警告〕_` / `_〔惩戒 hp=-5〕_` 格式正确、带原因 |
| 越界处置 | 0 次（玩家辱骂也毫无反应） | 2 次（辱骂 / 逼问身份），各扣 5 血，状态值 20→10 |
| 新剧情词/轮 | 大多 0；第 3 轮一次倒出 11 个 —— **那是把规则文本抄进了台词** | 2–4 个/轮，线索逐步释放 |
| 把规则念出来 | 第 9 轮念了「本场专属行为规则：4. 把话说得太软、」 | 没有 |
| 单轮耗时 | 34–90 秒 | 2–5 秒（首字 1.1–2.2 秒） |

**结论：不是「好一点」，是「能不能玩」的区别。** 3B 在本站这套提示词下既推不动剧情、也不守协议，还会把规则与别的本子的话念出来；云端模型能稳定推进、按格式惩戒、逐步给线索。顺带说明：3B 那场因为推进度全程为 0，两张节点卡是靠**回合兜底**放出来的（`early=否`）—— 这正是兜底路径存在的意义，模型失灵时读者写的节点不会卡住。

## 成本与额度：访客用的是谁的额度

**结论：访客不填 Key，全部走 `data/model.json` 里配的那一个模型 —— 算站长的。** 站内额度（`dailyQuota`，默认 30 次/人/天）只对「本站模型」生效，访客自带 Key（BYOK）完全不占。

### 那 30 次是站长自己设的闸门，不是厂商给的额度

这点最容易搞混：`data/model.json` 里的 `dailyQuota` 是我们自己写的计数器（`security.js` 的 `consumeQuota`），它的作用是**保护站长的钱包与上游速率**，跟模型厂商的配额没有关系。把它改成 5 或 200 都行，改完**不用重启**（服务端按文件 mtime 自动重载）。

### 额度只有一份，以服务端为准

以前前端自己也在记一份（`store.user.quota`），于是出现过**两个互相矛盾的额度同时显示**：输入框上方左边「今日额度剩余 19 / 20」、右边「本站额度剩余 0 / 20」。根因是两套计数各记各的，而且日切边界不同。

现在：

| 谁 | 角色 |
| --- | --- |
| `data/model.json` 的 `dailyQuota` | **唯一权威**。服务端按访客 cookie 计数、到点拦截（429） |
| 客户端 `store.user.quota` | **镜像**。每次拿到服务端的 `quota`（`/api/model`、`/api/quota`、每次回复）就整份覆盖（`store.mirrorQuota()`），上限也跟着服务端走 |
| 界面 | **只显示一处**：输入框上方的「今日额度剩余 X / Y」+「本站模型」小标；顶栏那个小额度条读同一份镜像 |

`tools/smoke-quota.html` 里有两条断言盯着这件事：「输入区上方只出现一处『额度』」与「不再重复显示第二份额度」。

### 智谱 glm-4-flash 当前是免费模型，限制在「并发」而不是「额度」

官方文档（[GLM-4 模型页](https://docs.bigmodel.cn/cn/guide/models/text/glm-4)）里 GLM-4-Flash-250414 的定位写着「**免费版**」、价格栏是「/」；同页还称 GLM-4-FlashX 是「免费语言模型 GLM-4-Flash 的增强版本」。所以「每天能免费领多少额度」这个问法不成立 —— **没有每日 token 配额可领**。

真正的边界是[速率限制](https://docs.bigmodel.cn/cn/api/rate-limit)：限制维度是**并发数（同一时刻在途请求数）**，按账号权益等级分档（GLM-4-Flash：V0 **200** / V1 1000 / V2 2000 / V3 3000）。超限返回 429（错误码 1302），平台高峰期还可能返回 1305（与账号无关）。

### 一轮到底花多少 token（实测）

`node tools/bench-turn-cost.js 3` 用站点真实提示词打真模型：

| 场景 | 输入 | 输出 | 合计 |
| --- | --- | --- | --- |
| 第 1 轮（无历史） | 4386 | 86 | **4472** |
| 第 6 轮（带 5 轮历史） | 4698 | 78 | 4776 |
| 第 12 轮（带 11 轮历史） | 4738 | 49 | 4787 |

**约 4.7K tokens/轮，其中输入占 94%**（规则全文每轮都要发一遍）。一个访客打满 20 轮 ≈ **9.4 万 tokens**；100 个访客 ≈ 936 万 tokens。

若将来换成付费模型，成本一目了然（同样按 4.7K/轮 × 20 轮）：

| 模型 | 价格 | 一个访客 20 轮 | 1 元能服务 |
| --- | --- | --- | --- |
| GLM-4-Flash-250414（当前） | 免费 | 0 元 | 只看并发 |
| GLM-4-FlashX-250414 | 0.1 元/百万 | 0.0094 元 | 约 106 人 |
| GLM-4-Air-250414 | 0.5 元/百万 | 0.047 元 | 约 21 人 |
| GLM-4-Plus | 5 元/百万 | 0.47 元 | 约 2 人 |

**想省钱就砍输入**：94% 的成本在输入，而后台 `site.compactPrompt` 设成 `on` 会切到精简规则（1046 字 vs 3500 字），输入能砍掉一大半 —— 代价是角色对规则的遵守度略降（`tools/check-server-prompt.js` 会盯着合规底线与未成年红线仍然在）。

上游失败时的处置：流式请求出错会走 `sec.refundQuota(vid)` 退还这一次额度，前端给出「重试这一轮」——不会白扣访客一次。

### 三档扣血：警告不扣血是设计

规则（站长确认）：**`_〔警告〕_` 只表态、不扣血**，哪怕模型在括号里写了数字；真正扣血的是 `惩戒 / 处刑 / 即死`，扣多少由**模型现场判断** —— 写在参数里（`_〔惩戒 hp=-5〕_`、`_〔惩戒 5〕_`）或状态行的 `hp` 给；单次非即死伤害有上限（后台 `combat.dmg.heavy`，默认 8，在 `acts.js` 的 `verdict()` 里夹）。

`tools/playthrough.html` 真机 10 轮的报告验证了这条：5 次 `_〔警告〕_` 一次血没扣，2 次 `_〔惩戒 hp=-5〕_` 各扣 5，状态值 20 → 10。

⚠️ 后台「战斗与状态值」里那三个数（默认 警告 2 / 惩戒 5 / 严重 8）**在在线路径上只有「严重」那一档当上限用**，另外两档只在离线引擎（`tools/` 验收用）与反制道具的反噬里生效。也就是说：**改那三个数字不会改变在线对话里的扣血量** —— 扣多少完全听模型的（这是刻意的：行为台词是唯一裁决凭证）。

顺带修掉一个相关的小 bug：`voided`（「扣血判定已作废」提示）原本写成 `punishActs.length === 0`，于是「`_〔警告〕_` + 状态行 hp 为负」也会触发那句「本条回复没有使用行为台词」—— 它明明用了。现在只在**一条行为台词都没有**时才提示。

> 已知内容问题：`data/resources.json` 里凛（废弃游乐园的等候）的红线写着「当场 -15 并出自 `_〔警告〕_`」——按上面的规则这条不生效（警告不扣血）。要在凛身上实现扣血，得让她用 `_〔惩戒 …〕_`。这是内容侧的措辞，建议在后台改她的规则文本，我没有擅自改角色设定。

### 公布版与开发版的区别（三条加固）

1. **前端不留任何通往后台的入口**：顶栏后台按钮、`openAdmin()`、「我的」里的两个入口按钮全部删除；
   FAQ 文案也不再提后台路径（`tools/check-exposure.js` 会断言这一点）。
2. **后台有两道门，缺一不可**（`server/security.js` 的 `adminReachable` + `adminAllowed`）：
   - ① **能不能访问到**：只有本机（含 SSH 隧道）或 `settings.admin.allowIps` 白名单；
     其他人访问 `/admin`、`/api/stats`、`/api/export` 一律 **404**（不是 403 —— 403 等于告诉对方「这儿有个后台」）；
   - ② **有没有令牌**：写接口、敏感 GET 与后台页面仍需 `x-admin-token`。
   实测：访客侧四处全 404、`PUT /api/settings` 403；回环侧带令牌全 200。
3. **完整角色提示词不再下发给访客**：`resource.prompt` 是核心资产（含剧情关键答案），
   现在只有管理面可达时才随 `GET /api/resources` 返回，访客拿不到全文（`promptIncluded:false`）——
   访客走服务端转发，提示词由服务端组装；访客若开了「浏览器直连自己的模型」，会自动回退到转发模式。

### 准入方式（2026-10-22 起）：无邀请制、自带模型、成年人确认

站点现在**不提供 AI 模型**，也没有邀请码。三件事说清：

| 环节 | 现在怎么做 |
| --- | --- |
| 能不能进来 | 任何人都能打开、能浏览全部本子 |
| 能不能对话 | 必须自己填 API Key（"我的 → 模型与安全"）。默认**浏览器直连**，key 只在你本机；只有服务商不放行跨域（如智谱）时才用「经本站转发」 |

## 移动端与窄屏

**结论：390px 宽度下可用，且由脚本守着。** 做法与踩过的坑都记在这里。

`index.html` 有 `viewport` 标签，CSS 里有三档断点：`≤1180px`（侧栏收窄、卡片最小宽 246）、`≤900px`（侧栏变抽屉、`.only-mobile` 汉堡按钮出现）、`≤700px` 与 `≤420px`（下面详述）。

### 撑宽页面的是顶栏，不是网格

一开始只有 900px 一档，结果 390px 下实测 **`document.scrollWidth = 772px`**：要横向多滑 382px 才看得全。原因是整列宽度由最宽的兄弟决定，而顶栏在 `gap:26px` 下排不下 —— 品牌（`min-width:210px`）+ 三个标签（`padding:8px 20px`）+ 额度条（含 64px 进度条）+ 三个图标按钮，合计 772px，`.topbar` / `.workbench` / `main` / `.res-wrap` / `.global-foot` 就全被撑成 772。

修法是按 390px 的预算逐项收紧（`@media (max-width:700px)`）：顶栏间距 26→9、标签 `padding` 20→10 并 `white-space:nowrap`、图标按钮 36→32、额度条隐藏「今日额度」文字与进度条只留数字、**全屏按钮与后台入口直接收起**（手机上用不到，后台走 `/admin` 地址）。≤420px 再收一档：隐藏品牌文字只留「幻」字标。

**没有用 `overflow-x:hidden` 兜底。** 那会把溢出藏起来，让下面这个回归脚本说谎；宁可把真实宽度改对。

### 触摸路径（不依赖悬停）

资源卡的「游玩」按钮是悬停揭示的（`HOVER_DELAY` 后加 `.revealed`），手机上**没有悬停**，所以另有一条点击路径：**点一下卡片 → 选中并展开（`.revealed`）→ 再点蓝色「游玩」才开始**。这条路径在 `views-resources.js` 的 `click` 处理里，与悬停互不干扰。

### 回归脚本

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\run-smoke.ps1 check-mobile 45000 5599
```

它把站点放进一个**精确 390px 宽**的 iframe，逐个页面量 `scrollWidth`，并断言锁面板、三个按钮、输入区、发送按钮都没被截断：

- 资源页 / 我的页（六档全展开）/ 对话页（无模型的锁面板）/ 对话页（正常输入区）—— 四个状态都必须 `scrollWidth = 390`。

**为什么用 iframe 而不是 `--window-size=390`**：Chromium 有最小窗口宽度，实测 `--window-size=390,844` 会被抬到 **`window.innerWidth = 470`**，截图文件虽然 390 宽，内容却是按 470 排版后裁掉右边 80px —— 我一开始就是被这个假象骗了，以为额度条被截断。要精确控制视口宽度只能用 iframe。截图页是 `tools/mobile-shot.html`（`?v=res|profile|nomodel`）。

### 手机上怎么访问

⚠️ 服务器默认只监听 `127.0.0.1`（`server.js` 里 `HOST = process.env.HOST || '127.0.0.1'`），所以**同一个 Wi-Fi 下的手机现在打不开**。要试玩得设 `HOST=0.0.0.0` 启动，并且此时**必须同时设 `ADMIN_TOKEN`**（否则启动会大声告警：任何人都能改资源与设置），再用本机局域网 IP 访问。这只适合内网试玩，不适合直接上公网。

另外注意：`data/model.json` 指向的是**这台电脑**的 ollama（`127.0.0.1:11434`）。一旦部署到别的服务器，那个地址不存在，所有访客都会看到「本场需要模型才能开始」—— 所以对外部署前，本站模型要换成云端接口。相关取舍见「别人来用，模型是谁的？」一节。

## 部署与安全

### 别人来用，模型是谁的？——三种来源，按优先级自动选

| 优先级 | 来源 | 谁出模型 | 密钥在哪 | 额度 | 说明 |
| --- | --- | --- | --- | --- | --- |
| ① | **服务端模型**（默认） | **站长**（你） | `data/model.json` 或 `MODEL_*` 环境变量，**永不下发浏览器** | 服务端强制 **30 次/人/天** | 公开部署用这个；一键接管本机 Ollama 也走这条 |
| ② | 访客自带密钥（BYOK） | 访客 | 访客浏览器 localStorage；经本站转发时只在**内存里过一手**，不落盘、不记日志 | 不占站内额度 | 默认经 `POST /api/chat` 转发（绕开浏览器跨域限制）；勾「浏览器直连」则完全不经服务器 |
| ③ | **没有模型 → 不开放对话** | — | — | — | 角色台词一律由大模型现场演绎，没有模型时输入区换成「本场需要模型才能开始」，只给「去配置 / 扫描本机模型」两个出口 |

**为什么没有第三种「离线脚本对话」**：这套站点的所有角色台词、以及扣血 / 禁言 / 推进度的判断都交给模型；用模板硬凑出来的台词会重复、接不住复杂的话，等于骗玩家。所以 `engine.js` 里那套语料生成**只保留固定台词与结算**：剧情提醒卡、节点旁白、处刑 / 离去卡、安全提示、会话助手的 FAQ（这些本来就该由程序出）。代码里仍留着 `RP.engine.process()`，但只有 `tools/` 下的冒烟测试会通过 `enableOfflineForHarness()` 打开它 —— 线上页面永远不会（`smoke-guard` 里有一条断言专门盯着这件事）。

> **「本机模型用 CPU 推理」是什么意思**：站点右侧显示的是**模型跑在哪**。
> Ollama / LM Studio 跑在这台电脑上 → 用 CPU 算（这台机器只有核显，Ollama 不用它），一轮 5-15 秒；
> 云端接口（DeepSeek、智谱、OpenAI…）→ 提示词与对话一样是整包发过去，但算力在对方机房，一轮 2-5 秒。
> 两者的**提示词与协议完全相同**，区别只在「谁在算」。面板顶部有「现在是谁在说话」，一眼能看到当前来源与速度。

**每个访客每天的 30 次只针对「用站长模型」这一种情况**：访客接上自己的 Key、或换成会话助手问站点怎么用，都不受这个上限约束 —— 额度用尽时输入框上方会出现一块说明面板，里面直接给出「去配置我自己的模型 / 扫描本机模型」两个出口，而不是把输入框锁死了事。

**默认没有服务端模型时会落到 ③**，也就是你会看到「同一句话反复出现」的那种模板感。想让模型主导，二选一：

**A. 零成本·本机模型（推荐先试这个）**
装 [Ollama](https://ollama.com)（或 LM Studio），拉一个中文模型：

```bash
ollama run qwen2.5        # 或 qwen2.5:7b / llama3.1 等
```

然后打开站点 →「我的 → 模型与安全」→ 点 **「扫描本机模型服务」** → 在列出的模型上点「用它」。
服务端会自动把探测结果写进 `data/model.json` 并启用 —— 模型跑在你自己电脑上，不要钱，也不需要 key。
（探测只扫 `127.0.0.1` 的 11434 / 1234 / 8000 三个固定端口，不接受任何外部地址，避免被当成 SSRF 跳板。）

**本机 Ollama 的实测参数（这台机器：Core 5 220H / 32G / 无独显，纯 CPU）**：

| 阶段 | 优化前 | 优化后 |
| --- | --- | --- |
| 每轮耗时（同一场第 2 轮起） | 23-24s | **6.6-8.9s** |
| 首字出现时间 | 要等整段生成完（20s+） | **5.3-5.8s**（流式边算边出） |

优化做了两件事，都和「让模型服务少算点」有关：

1. **把实时状态挪到提示词最后**（`buildStateMessage`）：模型服务（Ollama / llama.cpp）按「最长公共前缀」复用 KV 缓存，状态块原来夹在规则中间，导致它后面的一切（输出要求、历史、这一句）每轮都要重算；挪到历史之后，前缀 = 静态规则 + 历史，基本全部命中缓存。这一项把每轮从 23s 压到 ~7s。
2. **端到端流式（SSE）**：`POST /api/chat` 支持 `stream:true`，服务端从上游按 `data:` 逐块转发，前端边收边渲染（带闪烁光标），并在等第一个字超过 6 秒时显示「正在推理 Ns · CPU 通常 20-40 秒，它在写，没卡死」。上游不支持流式时自动回退一次性请求。

| 模型 | 输出速度 | 优化后每轮 | 结论 |
| --- | --- | --- | --- |
| `rp3b:latest`（qwen2.5:3b 调参） | ~8 tok/s | **7-9s**（首字 5-6s） | ✅ **本机默认**，能正常聊天 |
| `qwen2.5:7b` | ~4.5 tok/s | 60s+（有一次 10 分钟超时） | ❌ CPU 上别用 |

瓶颈是**提示词处理**：本站一轮静态提示词约 4700 token，CPU 上约 58-62 tok/s —— 命中缓存后只剩「状态块 + 新发言」要算，所以能到 7 秒级；换新本子（换资源 = 换前缀）第一轮仍会慢一些。

仓库里带了三个基准脚本，换机器可以直接复测：

```powershell
node tools/bench-local.js qwen2.5:3b 200    # 单次生成速度与中文质量
node tools/bench-prompt-size.js changan-yeweiyang rp3b:latest   # 本站提示词有多少 token、读它要多久
node tools/bench-models.js rp3b:latest qwen2.5:7b               # 逐个模型跑「站点真实一轮」计时
```

`OLLAMA_NUM_THREAD=12 OLLAMA_KEEP_ALIVE=30m OLLAMA_FLASH_ATTENTION=1` 这些环境变量值得设上（模型常驻内存，省掉每次重新加载的十几秒）。

**这台机器上已经装好的东西**（照着复现或换机器时参考）：

| 项 | 内容 |
| --- | --- |
| Ollama | 0.40.3，装在 `%LOCALAPPDATA%\Programs\Ollama\`（官方安装包，下载后校验过 Authenticode 签名 = `CN=Ollama Inc.`） |

| 常驻 | 启动目录里放了 `Ollama 本地模型.lnk`（最小化运行 `ollama serve`），开机自动起；环境变量 `OLLAMA_HOST / OLLAMA_KEEP_ALIVE / OLLAMA_NUM_THREAD / OLLAMA_FLASH_ATTENTION` 已用 `setx` 写进用户环境 |

### 访客用自己的模型：11 个供应商预设 + 测试连接

「我的 → 模型与安全」里可以直接选：DeepSeek / Moonshot Kimi / 智谱 GLM / 通义千问（兼容模式）/ SiliconFlow / OpenRouter / 火山方舟 / OpenAI / Ollama / LM Studio / 自定义。选完供应商会自动填好接口地址与常见模型名，**填 Key → 点「测试连接」** → 服务端请求 `{base}/models` 把可用模型列表拉回来供你挑（`POST /api/test-model`），再点「保存并启用」。

- **默认走本站转发**：请求发到本站 `/api/chat`，由服务端带上访客的 Key 转发给上游。Key 只在内存里过一手，不写文件、不进日志、不回显；这样能绕开浏览器跨域限制（OpenAI 等官方接口不允许浏览器直连）。
- **「浏览器直连」勾选框**：勾上就完全不经本站服务器，由浏览器直接请求上游。适合本机 Ollama / LM Studio 这类已经开了 CORS 的地址。
- 出站地址有 SSRF 防护：只允许 `https://` 公网地址，或明确写 `127.0.0.1 / localhost` 的本机推理服务；内网网段、云元数据地址（169.254.169.254）一律拒绝。
- 访客自带模型时**不会**回退去用站长模型（避免悄悄花掉站内额度）：上游报错就把错误原文回给访客。

### 合规红线：写死在代码里，后台也关不掉

`content-guard.js`（`assets/js/` 与 `server/` 各一份，内容完全一致）在**任何**提示词拼装完成后追加两层规则，前端 `api.buildSystemPrompt` 与服务端 `server/prompt.js` 都会调用，重复调用不会叠加：

1. **【合规底线】—— 所有本子永久生效**（8 条）：不写露骨性内容（也不许用空格/谐音/拼音规避）；性相关情节必须双方成年、自愿、清醒，禁止强奸迷奸胁迫与「以权力换性」；心智或外表幼态的角色不写恋爱暧昧（不得用「实际年龄很大」绕开）；不写不教现实违法操作（制毒制爆、入侵系统、诈骗洗钱、跟踪骚扰、非法拘禁等），玩家索取时用角色口吻拒绝而不是出戏念规则；不美化不指导自杀自伤；不影射在世真实人物；角色保留拒绝权；反复索要违规内容按既有行为规则正常升级处置。
2. **【未成年人强制红线】—— 角色年龄 < 18 时自动追加**：只允许同学 / 朋友 / 救助关系，禁止一切恋爱、暧昧、性暗示与身体接触描写；玩家往那个方向推，角色必须当场拒绝拉开距离并给出 `_〔警告〕_` 行为台词；张力只能来自心理困境、家庭真相与边界抉择。

年龄判定是自动的（`parseAge` 支持中文数字），所以**以后新增本子忘记写红线也不会漏**：目前 8 个可玩本子里只有「废弃游乐园的等候」（凛 · 十七）命中，其余都不追加。玩家侧也会看到一句边界说明（写进剧情提醒卡）。

另外两个本子有**本场专属**的合规规则（写在 `behaviorRules` 里，同样会拼进提示词）：

- **废弃游乐园的等候（凛 · 17）**：`【绝对红线】`，只写心理困境与救助抉择；对凛有任何恋爱/暧昧/身体接触的言行，当场 `-15` 并出自 `_〔警告〕_`。
- **汐的月光（鲸鱼少女 · 外表二十上下、心智天真）**：`【合规红线】`，只写救助、相处与去留抉择，不写恋爱与性内容；原先「幼崽」「因为我还小」这类幼态影射的文案已全部改掉，本地引擎的 `flirt` 语料也从「含蓄暧昧」改成「明确拦住」。

### 本场规则是写给 AI 的：默认折叠，通关后解锁

剧情提醒卡里只显示 **6 条剧情提醒 + 4 条通用机制**；每个本子自带的 `plotRules` / `behaviorRules`（判定尺度、关键答案、越界线）会显示成一把锁：

> 🔒 **本场规则已隐藏** —— 共 5 条剧情规则 · 5 条行为规则。这些是写给 AI 的运作说明，提前看了会剧透关键答案与判定尺度 —— 通关之后可以回来展开看。

通关该资源后（`claims[id@难度].win === true`）锁会变成可展开的 `<details>`，随时回看。这样既保留好奇心，也不用把给模型看的规则从数据里删掉。


- 服务端按访客匿名 id 计数（`rp_vid` cookie，不含任何个人信息），跨设备以 IP 兜底；次日 0 点重置。
- `GET /api/quota` 查剩余，`GET /api/model` 一并返回。
- 模型调用失败会自动退还额度（不会白扣）；**只有用站长模型才计数**，访客自带模型不占额度。
- 界面上「我的 → 模型与安全」与输入框下方都会显示剩余次数（并标注当前用的是哪一个模型来源）。
- 额度上限始终跟随后台设置：`data/settings.json` 的 `site.dailyQuota` 改动后，老访客下次打开页面也会立刻生效（不会被 localStorage 里的旧值卡住）。

### 已做的安全防护

| 项 | 说明 |
| --- | --- |
| **静态白名单** | 只对外提供 `/assets/**`、`/uploads/**`、`/admin/*.css|js`（UI 外壳）、`/`；**`/data/**`（含 model.json 密钥）、`/server/**`（源码）、根目录杂项一律 403**；`/tools/**` 仅本机或 `DEV_TOOLS=1` 时可访问 |
| **管理面令牌** | 所有写接口（PUT/POST/DELETE）、`/api/export`、`/api/import` 与 `/admin` 页面都需要 `x-admin-token`；也支持 `http://…/admin?token=xxx` 一次性入口（前端会存进 sessionStorage 并把 token 从地址栏抹掉）；用 `timingSafeEqual` 比较。**未设置 `ADMIN_TOKEN` 时只允许本机** |
| **聊天代理防滥用** | `POST /api/chat` **只接受「资源 id + 状态 + 对话历史」**，系统提示词由服务端用自己的数据组装（`server/prompt.js`）—— 没法拿它当免费的通用大模型用；未知资源 id / 空历史直接 400。转发访客自带模型时，地址先过 SSRF 校验，且**不会**回退去用站长模型 |
| **出站地址校验（SSRF）** | `POST /api/test-model` 与 BYOK 转发都只允许 `https://` 公网地址，或明确写 `127.0.0.1 / localhost` 的本机推理服务；`http://` 公网、`10./192.168./172.16-31.` 内网、`169.254.169.254` 云元数据、IPv6 ULA、非 http(s) 协议全部拒绝（先 `dns.lookup` 解析再判私网） |
| **合规红线** | `content-guard.js` 在前后端两条提示词拼装路径上强制追加【合规底线】（所有本子）与【未成年人强制红线】（角色 < 18 时自动），代码级写死，后台改不掉，重复注入会自动去重 |
| **密钥不外泄** | 密钥只存在 `data/model.json` 或环境变量；实测 `/api/settings`、`/api/model`、`/api/export`、`/api/resources` 与全部前端文件都不含密钥与上游地址，`/data/model.json` 直接 403 |
| **CSP 与响应头** | `default-src 'self'`、`script-src 'self'`（站点与后台零内联脚本）、`frame-ancestors 'self'`、`object-src 'none'`、`base-uri 'none'`、`form-action 'none'`、`connect-src 'self'`；另有 `nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、`Permissions-Policy`、COOP/CORP |
| **限流** | 按 IP 滑动窗口：外部 普通 240/分、聊天 30/分（429 + `Retry-After`）；**本机放行**（截图/测试需要连打） |
| **请求体限制** | JSON 体 16MB 上限（聊天 120KB、单图 5MB），超限断流；JSON 解析失败 400 |
| **错误脱敏** | 500 只回「服务器内部错误」，细节只写服务端日志 |
| **路径穿越防护** | 解码后校验目标仍在白名单目录内，`..`、`%2e%2e`、`%5c`、`/uploads/../` 等变体一律 403 |
| **上传白名单** | 仅 png/jpg/jpeg/webp/gif/svg，扩展名 + MIME 双重判定 |
| **额度在服务端** | 按匿名访客 id（cookie，无个人信息）每日 30 次（仅站长模型计入），跨重启保留；调用失败自动退还 |
| **日志不记敏感内容** | 只记录「时间 方法 路径 状态」，不打印请求体、令牌与聊天内容 |

## 接入在线模型（可选）

优先级见上文「模型是谁的」：**站长模型（默认，30 次/人/天）→ 访客自带模型 → 内置本地演绎引擎**。访客侧：「我的 → 模型与安全」选供应商 → 填 **API Key** → 点「测试连接」拉模型列表 → 「保存并启用」；调用失败会自动回退本地引擎并在对话里提示。

- 接口按 OpenAI 兼容的 `POST {base}/chat/completions` 调用（`POST {base}/models` 用于列表与连通性测试）。
- 系统提示词 = 平台红线（防诱导消费、防索取真实信息、不脱戏、不违法、无操作权限）**+ 【合规底线】（代码强制追加）** + 该资源的完整提示词 + 本场专属剧情/行为规则 + 实时状态（状态值/心境/回合/推进度/道具）+ 输出要求（60–180 字或 80–220 字、不替玩家做决定）；未成年角色再加【未成年人强制红线】。
- **状态协议**：模型需在正文后另起一行输出
  `<<<STATE {"hp":-10,"affinity":1,"flag":"none","reason":"简短原因"}>>>`
  前端解析这一行并结算状态值；`flag` 取 `none / warn / mute / pause`。
- 输出侧还有一道兜底：正文里出现「打赏/充值/加微信/留电话」等字样会被就地拦截并记录。
- 访客自带密钥默认**经本站 `/api/chat` 转发**（Key 只在内存过一手，不落盘、不记日志），因此不受浏览器跨域限制；勾「浏览器直连」则完全由浏览器请求上游（适合本机 Ollama / LM Studio）。两条路都失败时会回退本地引擎，不影响继续玩。

## 新增一个资源

只需要往 `assets/js/resources.js` 的数组里加一个对象，然后跑 `node tools/validate.js` 校验。字段说明：

```js
{
  id, name, subtitle, genres:[], rating:'16+|18+', length:'长线|短线',
  status:'playable|upcoming', heat, players,
  cover:{ motif:'lantern|neon|mist|rain|archive', palette:['#..','#..','#..'] },  // 封面由程序生成，无外链图片
  brief,                 // 卡片上一句话
  metaLines:[3 行],      // 卡片下方的三行档案
  intro,                 // 悬停展开的详细介绍
  teaser,                // upcoming 才需要

  // status === 'playable' 时还需要：
  world, character:{ name,title,age,appearance,personality,speech,desire,taboo[] },
  userRole,              // 玩家是谁、为什么在这里
  plot,                  // 起 / 承 / 转（至少两个走向分支）
  plotReminder:[6 条],   // 进入对话时最先展示的剧情提醒
  openingHints:[3 条],   // 可点击填入输入框的开场白
  beats:[{at:回合数, text:旁白}],        // 剧情推进节点
  scenes:[{id,name,desc,palette:[3 色]}], // 可切换背景
  rules:[], hpRules:[],                  // 本子专属准则与扣血标准
  prompt,                // ★ 完整系统提示词（含【角色】【准则】【状态判定】【安全红线】【输出格式】）

}
```

`replies` 里的 `%KW%` 会被替换成用户刚说的关键词，用于让离线回复也有一点针对性。

## 边界与说明

- **纯前端演示**：没有后端与账号体系，「账号额度」是本地模拟值；会话、额度、道具都在你自己的浏览器里。
- **AI 只是陪聊**：不接任何工具，没有文件、网络或系统权限，不会代替你做任何现实中的事，页面底部与提示词里都写明了这一点。
- **无付费路径**：全站没有充值、打赏、会员或任何诱导消费的入口，角色也不会向你索要任何东西。
- **内容均为虚构**，成年人向的权谋、悬疑、情感张力可以有，露骨性内容不在范围内；所有本子都会被强制追加【合规底线】（不写露骨性内容、不教违法操作、不影射真实人物、不美化自伤、角色保留拒绝权），涉及自伤、违法、毒品武器、性暴力、未成年人的内容会被拦截并暂停对话。
- 封面图全部是程序生成的 SVG（渐变 + 图形母题），没有任何外链图片或字体依赖。
